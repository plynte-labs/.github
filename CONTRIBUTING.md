# Contributing to Plynte Labs

Thank you for helping improve Plynte Labs. Contributions should be small, verifiable, and easy to review.

## Quick path

1. Read the target repository README.
2. Create a branch from that repository's default branch.
3. Make one focused change.
4. Run the repository checks.
5. Open a pull request with context and verification notes.

## Standards

| Area | Expected practice |
|------|-------------------|
| Commits | Use Conventional Commits: `feat:`, `fix:`, `docs:`, `chore:`. |
| Scope | Prefer small pull requests over broad rewrites. |
| Tests/checks | Run the available project checks before asking for review. |
| Documentation | Update docs when setup, behavior, or public contracts change. |
| Language | Code and technical artifacts use English unless the repository says otherwise. Public organization docs may be bilingual. |

## Pull request checklist

- [ ] The change has one clear purpose.
- [ ] The user-facing impact is explained.
- [ ] Relevant checks were run.
- [ ] Docs were updated when needed.
- [ ] The PR description says what reviewers should focus on.
